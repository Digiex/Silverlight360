Libraries¶

Class libraries for Silverlight360 apps. Each builds as a Silverlight360 class library (Class libraries of your own): an app references its project, or its DLL from a release, and the SDK's build puts the DLL in the app's package and makes its native image with the app's own.
Silverlight360.Common The SDK's own: NativeBuffer and BigEndian for native calls, DebugLog, DirectionalFocus and Screenshot. Every app and library references it already.
Silverlight360.Https HTTP and HTTPS with TLS 1.2 and 1.3 and Mozilla's current root certificates: libcurl on Mbed TLS in a native DLL, https360.xex, called from C# through HttpsClient. Its drop-in sends an app's own WebClient and HttpWebRequest calls through it, for the sites the console's own HTTPS can't reach. Runs on consoles. Documentation, source and releases.

Silverlight360.Https¶

The platform's HttpWebRequest and WebClient do HTTPS with the console's own certificate authorities, which are years old: on a console they fail for sites such as example.com and github.com (Networking). Silverlight360.Https makes those requests with TLS 1.3 and Mozilla's roots, on any thread.

using Silverlight360.Https;

HttpsRequestCreator.Register();   // once: WebClient and HttpWebRequest now go through Silverlight360.Https
var web = new WebClient();
web.DownloadStringCompleted += (s, e) => Show(e.Error == null ? e.Result : e.Error.Message);
web.DownloadStringAsync(new Uri("https://example.com/"));

An app references Silverlight360.Https.dll and puts https360.xex and cacert.pem beside default.xex; see Adding it to an app. Its native DLL loads at 0x8D000000, a base free in a Silverlight app's process on the console: a native library of the app's own (Native code) needs another.

Adding one¶

A library for Silverlight360 apps can be listed here: open an issue or a pull request (Contributing) with what it does, where its documentation is, and whether it has run on a console.
